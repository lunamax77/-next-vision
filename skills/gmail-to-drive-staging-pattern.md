# メール添付ファイルを扱えないときの回避策(Driveへの退避)

下請け請求書チェックの自動化を作る過程で確立したパターン。AIがメールを直接扱う
経路(Gmail連携ツール)によっては、**メール本文は読めても添付ファイルの中身
(PDF等)までは読めない**ことがある。その制約に当たったときの回避策。

## 課題

「請求書が届いたら中身(金額など)をチェックしたい」という要求に対し、
使えるメール連携が添付ファイルの中身を返してくれない(添付の存在やファイル名は
わかるが、中身のテキスト・画像は取得できない)。これは連携方法によって差があるため、
**実際に1件試してから、できる/できないを確認する**のが確実(思い込みで
「読めないはず」と諦めない)。

## 解法: 添付ファイルだけをDrive等の「読める場所」に退避させる

1. メール側(Gmail等)の自動化機能(Apps Script等)で、**条件に合うメールの添付を
   定期的にファイルストレージへコピーする**処理を組む(例: 1時間ごと)。
2. 処理済みのメールには専用ラベルを付け、次回以降は対象から除外する
   (重複コピーを防ぐ)。**元のメールは削除・改変しない。**
3. 保存先のファイル名に、受信日・差出人などの由来情報を含めておくと、
   後から中身を見なくても検索・突き合わせがしやすい。
4. AI側は、ファイルストレージに退避されたファイルを読む(こちらは中身を読める)。
   「直近◯時間以内に追加されたファイル」を対象にすれば、定期チェックと
   自然に噛み合う。

```
[メール(添付PDF)] → 自動保存 → [Drive等のフォルダ] → AIが読んで中身をチェック
```

## 実装した際の要点

- 検索条件(件名・差出人ドメイン等)は、**自社が受け取る側の請求書だけを拾う**ように
  絞る(自社が発行した請求書を誤って対象に含めない、など)。
- 同名ファイルの重複保存を避けるため、保存前に同名ファイルの有無を確認する。
- この処理は「メールを読んで、添付をコピーするだけ」なので、原本(メール本文・
  添付そのもの)には一切手を加えない。原本不可侵の原則に反しない設計にできる。

## 応用できる場面

契約書・領収書・見積書など、**添付ファイルの中身を定期的にチェックしたい
あらゆる業務**に応用できる。使っているメール連携方法によって「添付が読めるか
どうか」は変わるので、この回避策が必要かどうかは都度確認する。
