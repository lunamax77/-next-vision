# 売掛・買掛スプレッドシートの読み取り方

竹村代表グループの「売掛・買掛」参照スプレッドシートを解析するときの、実際に検証済みの
やり方。`docs/routines/daily-ledger-snapshot.gs` の `readLedgerFromSheet` / `pickPair_` が
実装そのもの。ここでは**考え方とハマりどころ**をまとめる。

## シートの構造(前提)

- スプレッドシートは**タブが月ごと**(7月、8月…)。同じ社名でも月によって金額が違う。
  比較・突き合わせをするときは必ず「どの月のタブか」を先に決める。
- 各タブの中に「**売掛**」「**買掛**」という見出しが**同じ行に横並び**で出てくる箇所があり、
  その下に「取引先名」と「金額」が並ぶ2つのブロック(売掛側・買掛側)が続く。
- 見出しの前後に**備考列**が挟まっている(例:「社長作成」「1営業日17時」といった処理メモ、
  「個人事業主」「派遣社員」といった属性ラベル)。これらは取引先名でも金額でもないので
  読み飛ばす必要がある。
- 売掛・買掛の見出しが無いタブ(スタッフの稼働表など)も同じスプレッドシート内に混在する。

## 読み取りアルゴリズム

1. **見出し行を探す**: 先頭から一定行数(目安80行)を見て、同じ行の中に「売掛」という
   セルと「買掛」というセルが両方あり、かつ「買掛」が「売掛」より右にある行を見出し行とする。
   見つからなければ、そのタブは対象外(稼働表などとみなしてスキップ)。
2. **列の範囲を決める**: 「売掛」列から「買掛」列の手前までが売掛ブロック、
   「買掛」列から行末までが買掛ブロック。
3. **各行から (取引先名, 金額) を1組拾う**: そのブロックの列範囲内を左から見て、
   - **数値が最初に現れた時点の値**を金額とする。
   - **金額より前に現れた文字列**を取引先名とする(空セルや、金額の後ろに出てくる
     文字列は無視する)。
   → これだけで、見出し列より左の備考(社長作成など)は「金額より前だが列範囲外」
     なので自然に無視され、金額の後ろに付くラベル(個人事業主など)も
     「金額より後ろ」なので無視される。
4. **ブロックの終わり**: 次に「売掛」または「買掛」という見出しセルが再び現れた行に
   来たら、そのタブのブロックはそこで終わり(次の月のタブへの巻き込みを防ぐ)。
5. **金額0の行もそのまま記録する**。「0 → 金額あり」になったときに「増加」として
   正しく検出するため、0を特別扱いして除外しない。

## 複数時点を比較するとき(前回比・前日比など)

- 同じ取引先が両方の時点に存在 → 金額の差分を見る(増減)。
- 前の時点に無くて今回だけある → 「新規」。
- 前の時点にあって今回無い → 「消滅」(ただし金額が0のまま消えた場合は無視してよい。
  0同士の比較に意味は無いため)。
- 複数の取引先で変化があるときは、**差額の絶対値が大きい順**に並べると読みやすい。

## 検証のやり方(ハマらないために)

- 本物のシートに近い「備考列あり・金額後ろにラベルあり・0値あり・見出し無しタブあり」
  という**意地悪なテストデータ**を用意し、抽出結果を目視確認してから本番に投入する。
  備考列やラベルを想定していないと、それらを取引先名や金額として誤って拾ってしまう
  バグに気づけない。
- Google Apps Script側の関数(`readLedgerFromSheet`など)は、Node.jsに`.cjs`として
  コピーし `module.exports` を足すことで、GAS特有のAPI(`SpreadsheetApp`など)を
  モックしたテストハーネスでロジックだけ検証できる。GAS上で毎回本番実行して試行錯誤
  するより速い。

## 原本の扱い

このシートは会社の原本データ。読み取り(`getValues()`など)のみを行い、
書き込み・編集は一切しない。抽出した結果は別ファイル(スナップショット・レポート)として
保存する(`docs/org/03-data-protection.md` の原本不可侵ルール)。
