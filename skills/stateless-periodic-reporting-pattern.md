# 記憶を持たない定期実行で「前回からの変化」を出す設計

定時報告(朝/昼/夕/夜)や売掛買掛の変化トラッキングを作る過程で確立した設計パターン。
**毎回まっさらな状態で起動するタスク**(記憶を持たない)でも、「前回から何が変わったか」
「今日はどれだけ積み上がったか」を出せるようにする一般的な考え方。同じ形の要求
(何かを定期的にチェックして差分を報告する)には、そのまま応用できる。

## 課題

定期実行のたびに新しいセッション/プロセスが起動し、前回の実行内容を覚えていない。
かつ、比較対象の元データ(スプレッドシート等)自体も「現在の値」しか保持していない
(履歴が残らない)。この状態で「前回比」「本日の累計」を出したい。

## 解法: チェックポイントをファイルとして積む

1. 実行のたびに、**その時点の値をタイムスタンプ付きのファイルとして保存する**
   (例: `2026-08-21_1152.json`)。ファイル名でソートすれば時系列になる。
2. 保存する直前に、**それまでのチェックポイント一覧**を読み、
   - 「直前(＝一番新しいもの、日をまたいでもよい)」
   - 「本日いちばん最初のもの」
   の2つを特定する。
3. 比較パターンをこの3ケースで自動判定する:
   - **直前が無い(初回)** → 基準値を記録するだけ。まだ比較できない旨を出す。
   - **直前が別の日** → その日の1回目の実行。「前日比」を1セクション出す。
   - **直前が今日のもの、かつ「本日いちばん最初」と同じ** → その日の2回目。
     直前比と本日累計が同じ値になるので、1セクションにまとめる(重複を避ける)。
   - **直前が今日のもの、かつ「本日いちばん最初」と別** → その日の3回目以降。
     「前回からの変化」と「本日いちばん最初からの累計」の2セクションを出す。
4. 「今日いちばん最初」を都度探索することで、日付が変わったことも自動検出できる
   (特別なリセット処理を書かなくても、日付が変われば自動的に「前日比」パターンに戻る)。

## 実装した際の要点

- 比較ロジック(名前ごとの増減・新規・消滅の判定など)は、
  「前回」と「今回」の2つのスナップショットを受け取って差分を返す**1つの純粋関数**に
  切り出す。呼び出し側でどのペアを渡すか(前回同士/本日最初との比較)を変えるだけで、
  上の4パターンすべてに同じ関数を使い回せる。
- 出力先(比較結果のレポートファイル)も同様にタイムスタンプ付きで残しておくと、
  後から「あの日の何時時点でどう見えていたか」を追える。
- この関数はGAS/Node.jsどちらでも動くように書き、**モックした疑似ストレージ
  (Map実装のフォルダなど)で複数時点をシミュレートしてテストする**と、
  本番のスケジュールを待たずに全パターン(初回/2回目/3回目以降/日またぎ)を
  一度に検証できる。

## 応用できる場面

在庫・案件の件数・KPIの推移など、「元データは現在値しか持たないが、
定期的に前回比・累計を知りたい」という要求全般に使える設計。
