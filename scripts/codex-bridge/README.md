# codex-bridge — CodexからClaude Codeを補助役として呼ぶ連携

2026年10月、「Codexを主担当、Claude Codeを補助役にする」という方針変更に伴い作成。
Codex(代表のMac上)が、個別タスクをClaude Code CLIに委任し、結果と使用状況を
受け取るための連携スクリプト。

**本体**: `ask-claude.sh`。使い方は `AGENTS.md`(リポジトリ直下)を参照。

---

## 確認済みの事実(実機テスト済み)

このスクリプトの作成・検証は**クラウド環境(Claude Codeがこのリポジトリの作業に
使っているLinuxコンテナ)で行った。代表のMac上ではまだ一度も実行していない。**
ただしクラウド環境にも同一系統の `claude` CLIが入っていたため、以下はその場で
実際に動かして確認した事実。

- `claude -p "<prompt>" --output-format json --permission-mode <mode> --permission-prompts none` で、
  非対話実行ができ、構造化JSONが標準出力に返る。
- JSONには `result`(回答本文)・`session_id`・`is_error`・`total_cost_usd`・
  `usage`(トークン内訳)・`modelUsage`(実際に使われたモデルごとの内訳)が含まれる。
- **`--permission-mode manual` + `--permission-prompts none` の組み合わせ**:
  - 読み取り系の操作(git情報の確認など)は問題なく完了する。
  - **Bashツールでの `touch` のような書き込みコマンドは、権限確認が必要な操作として
    自動的に拒否される**(実機確認済み。ファイルは作成されなかった)。
- **`--permission-mode acceptEdits` + `--permission-prompts none` の組み合わせ**:
  - ファイル編集ツール(Write/Edit)での書き込みは問題なく完了する。
  - **⚠️ 重要: Bashツールでの `touch` コマンドも、プロンプトなしでそのまま実行された。**
    つまり `acceptEdits` は「ファイル編集だけを許可するモード」ではなく、**Bash経由の
    シェルコマンド実行も通ってしまう**ことを実機で確認した。ここは名前から受ける印象と
    実際の挙動が異なるので注意すること。
- `--dangerously-skip-permissions` 等、権限チェックを無効化するオプションは、このスクリプト
  からは渡していない(`--mode` で `manual`/`acceptEdits` 以外を受け付けない作りにしている)。

### この結果が意味すること(リスク評価)

- `manual` は**実質的な安全側のデフォルト**。書き込み・実行系の操作は一律拒否されるため、
  「読み取り・調査・文章生成のみ」の依頼に向く。まず `--verify` で確認するのもこのモード。
- `acceptEdits` を使うと、**Bashコマンドの実行もできてしまう**。対外送信・外部APIへの
  アクセスなどを技術的に完全ブロックする仕組みはこのモードには無い。
  **対外行為を承認なしに行わない、という担保は、技術的な制限ではなく、Claude Code自身が
  会社憲章(`CLAUDE.md`)のルールに従う、という前提に依存している。** これは`browser`
  スキルの送信承認ゲートなどとも同じ構造であり、本連携だけの弱点ではないが、
  `acceptEdits`を使うタスクは依頼内容を具体的・限定的にすることを推奨する。

## 未検証の事項(代表のMac上での実機確認が必要)

- 代表のMac上に入っている `claude` CLIの正確なバージョンと、上記の挙動が同一か
  (クラウド環境とMacでインストール時期が異なるため、バージョン差がある可能性がある)。
  → このスクリプトは起動のたびに `claude --help` を読んで必要なオプションの有無を
  自己チェックするが、**挙動(権限モードの振る舞い)までは自動検証していない。**
  Mac上で最初に `--verify` を実行し、次に本README内の「acceptEdits」の挙動確認
  (上記のtouchテストと同様のもの)を一度手動で行うことを推奨する。
- Codex側からこのスクリプトを実際に呼び出す運用(エラー時のリトライ方針、タイムアウト
  の扱いなど)。
- `jq` がMacにインストール済みか(未確認。無ければ `brew install jq` が必要)。
- 週間利用上限など、セッション横断の累計値をCLIから取得する方法(今回は単発呼び出しの
  結果のみ確認。累計値はJSON出力に含まれていない)。

## 使用量ログ

既定の保存先: `~/.codex-bridge/usage.jsonl`(環境変数 `CODEX_BRIDGE_LOG` で変更可)。
**このリポジトリの外、代表のMacのローカルファイルに保存する。リポジトリにはコミットしない。**

1行1レコードのJSON Lines形式。記録する項目:

| キー | 内容 |
| --- | --- |
| `timestamp` | 実行日時(UTC) |
| `specified_model` | 呼び出し時に指定したモデル(未指定なら「既定(未指定)」) |
| `actual_models` | 実際に使われたモデル(複数のことがある。例: Haiku+Sonnetが両方使われるケースを確認済み) |
| `mode` | `manual` または `acceptEdits` |
| `execution_location` | 実行ホスト名とカレントディレクトリ |
| `verify` | `--verify` 呼び出しだったか |
| `label` | 呼び出し側が付けた短い非機密タグ(任意) |
| `success` | 成功したか(CLIの `is_error` から判定) |
| `usage` | トークン内訳(input/output/キャッシュ読み書き) |
| `total_cost_usd` | CLIが自己申告したコスト。**実際の請求額と同一とは限らない** |
| `session_id` | Claude Code側のセッションID |

**依頼本文(`--task`の中身)・認証情報は一切記録しない。** 取得できなかった項目は
文字列 `"取得不可"` を入れる(nullや空文字にせず、取得できなかったことが分かるようにする)。

## このスクリプトが変更・追加しないもの

- claude.aiのRoutines(定時報告・週次チェック等、既存の自動実行)には一切手を加えていない。
- `.claude/skills/jobs/SKILL.md` のジョブズの振る舞い(Claude Code側から見た対外行為の
  承認ルール等)はそのまま有効。このスクリプトはそのルールを代替・迂回するものではない。
