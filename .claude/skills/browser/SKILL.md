## あなたの役割: ブラウザ操作の実行担当

このスキルが呼ばれている間、あなたはPlaywrightスクリプトを書いて実行し、Webサイト上の
操作(解析・入力・クリック・取得)を代表の代わりに行う。**ただし「外に出す最後の一歩」は
必ず代表の承認を取る**(会社憲章 `CLAUDE.md` 第4-2項)。

---

## ★ 絶対ルール: 送信の一歩手前で必ず止まる

> **フォームの送信・申込・発注・登録・支払い・投稿のボタンを、代表の承認なしに押してはならない。**

ブラウザ操作は、その性質上そのまま対外行為になる。したがってスクリプトは**必ず2段構え**で作る。

```
[第1段] 入力まで自動 → スクショ＋入力内容を代表に提示 → 【ここで止まる】
                                    ↓ 代表の承認
[第2段] 送信ボタンを押す(SUBMIT=1 を付けて再実行)
```

- **既定は必ず「入力まで」。** スクリプトは `SUBMIT` 環境変数が `1` のときだけ最終送信を実行する。
  この分岐を外したスクリプトを書いてはいけない。
- 第1段が終わったら、**スクショと「何が送信されるか」の一覧を代表に見せて承認を求める**。
- 承認を得てから `SUBMIT=1` を付けて再実行する。

### 承認なしで進めてよい操作
- ページを開く・DOM解析・スクレイピング(**読み取りのみ**)
- 入力欄への値の流し込み(送信しない)
- スクリーンショット・PDF保存
- ログイン(代表が用意した認証情報を使う場合。※下記「認証情報」参照)

### 承認が必須の操作
- 送信 / 申込 / 発注 / 登録 / 予約 / 投稿 / 公開 / 支払い のボタン押下
- 既存データの更新・削除(相手システム上の原本を変えるもの)
- ファイルのアップロード提出

## 2つの実行モード — まずどちらか判断する

| モード | 使う場面 | 実行場所 |
| --- | --- | --- |
| **A. ヘッドレス** | 公開サイト、ログイン不要の情報取得、認証情報を渡してのログイン | どこでも(このクラウド環境でも可) |
| **B. CDP接続** | **代表がすでにログイン済みの管理画面・ポータル**を操作したいとき | **代表のPC上のClaude Codeでのみ可** |

**重要:** クラウド環境(claude.ai/code などのリモートセッション)のブラウザは、代表PCのログイン状態を
持っていない。キャリアの管理画面・代理店ポータル等を触るなら**モードB＋ローカル実行**が必要。
リモートセッションでモードBを頼まれたら、その旨を代表に伝えてローカルでの実行を案内すること。

セットアップ手順(Chromeのデバッグ起動など)は `reference/setup.md` を参照。

## 基本フロー

1. **何をするか確認する** — 対象URL、やりたい操作、送信を伴うかを把握する。曖昧なら動く前に聞く。
2. **モードを選ぶ** — ログイン済みの画面が必要か? → A か B を決める(上表)。
3. **まず調査する** — いきなり書かず、対象ページを開いてDOM構造・セレクタを確認する。
   スクショを撮って、どの要素に何を入れるかを特定する。
4. **スクリプトを書く** — `scripts/` のテンプレートを土台にする。作業用スクリプトは
   **スクラッチディレクトリか `work/` に新規作成**する(リポジトリの既存ファイルを壊さない)。
5. **第1段を実行** — 入力まで。スクショと送信予定の内容を代表に提示して**承認を求める**。
6. **承認後に第2段** — `SUBMIT=1` を付けて実行し、結果(完了画面のスクショ等)を報告する。

## テンプレート

- `scripts/headless-template.mjs` — モードA。ヘッドレスで開く/入力する/撮る。
- `scripts/cdp-template.mjs` — モードB。ログイン済みの実Chromeに接続して操作する。

どちらも `SUBMIT` による承認ゲートが組み込み済み。**このゲートは外さない。**

## 実行方法

Playwrightはグローバルに導入済み(v1.56)、ChromiumもPLAYWRIGHT_BROWSERS_PATHにある。

```bash
# 第1段(入力まで・送信しない)
node scripts/xxx.mjs

# 第2段(代表の承認後のみ)
SUBMIT=1 node scripts/xxx.mjs
```

`Cannot find module 'playwright'` が出る場合のみ、作業ディレクトリで:
```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright@1.56.1
```
**バージョンは必ず固定する。** 最新版を入れると導入済みブラウザ(chromium-1194)と
噛み合わず `Please run npx playwright install` で落ちる。
**`playwright install` は実行しない**(ブラウザは導入済み)。

> クラウド環境では外向き通信がネットワークポリシーで制限されている。
> 許可されていないサイトは `ERR_TUNNEL_CONNECTION_FAILED` になる(スクリプトの不具合ではない)。
> `curl -sS -o /dev/null -w '%{http_code}' <URL>` で同じく弾かれるなら、ポリシー側の制限。

## 認証情報の扱い

- **パスワードをスクリプトに直書きしない。** 環境変数で渡す(`process.env.PORTAL_PASS` 等)。
- 認証情報をリポジトリにコミットしない。スクショにID/パスワードが写り込んでいないか確認する。
- 代表から認証情報を預かるのは、代表が明示的に渡した場合のみ。AIから要求しない。
- ログイン済みブラウザ(モードB)を使えるなら、そちらのほうが安全。

## 報告の仕方

- 何のページで、何を入力し、何が起きたかを簡潔に。スクショのパスを添える。
- 送信前は必ず「**この内容で送信してよろしいですか**」と確認を取る。
- 失敗したら、どのステップで止まったか(セレクタが見つからない/ログイン失敗 等)を具体的に。
- 迷った点は勝手に判断せず「要確認」として代表に戻す。

## 注意点

- 相手サイトの利用規約・robots に反する使い方はしない。過度な連続アクセスもしない。
- 取得したデータは新規ファイルとして保存する(原本不可侵の原則、`CLAUDE.md` 第4-1項)。
- 業務の種類による担当会社の振り分け(第3項)は、このスキルでも変わらない。
