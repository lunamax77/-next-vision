## 目的

会話の中で「今日」「明日」「先週金曜」といった相対表現を使うと、AIは推測で日付を埋めがちになり、
実際の日付とずれる。長いセッションほど、会話の最初に把握した日付が古くなり、この種のずれが起きやすい。
このスキルは、そのずれを防ぐための最小の手続きを定義する。

## 手順

1. **必ずシェルコマンドで実時刻を取得する。** 推測・会話の流れ・画像のタイムスタンプからは判断しない。

   ```
   TZ='Asia/Tokyo' date '+%Y-%m-%d(%a) %H:%M JST'
   ```

   このリポジトリの利用者(竹村代表)は日本国内を前提とするため、**JST(Asia/Tokyo)を基準**とする。
   システム側のタイムゾーンが UTC 等になっている場合でも、必ず `TZ='Asia/Tokyo'` を指定して変換すること。
   （`date` だけを実行してシステムのローカルタイムゾーンをそのまま使わない。)

2. 取得した日付と、会話内でユーザーが使っている「今日」「明日」等の表現が一致しているか確認する。
   - ユーザーが日付を明言した場合(例:「本日は8/24です」)は、それを正として扱う。
     システム時刻と食い違えば一言確認する(ユーザー側の環境の時計がずれている可能性もあるため、
     こちらの計算結果を一方的に押し付けない)。
   - 画像(体組成計のスクリーンショット等)に表示された日付は **参考情報であり、実時刻の代わりにはしない**。
     機器の時計がずれていることがあるため、実時刻と食い違えば確認する。

3. 日付をまたぐ記録(`docs/personal/health/logs/` など)に書き込む前は、必ずこの手順で
   当日の日付を確定してから書く。「会話が始まってからの経過」や「前のメッセージで言っていた
   『明日』」を根拠に日付を推測しない。

## 注意

- 迷ったら、確認した日付を一言ユーザーに提示して確認を取るほうが、誤った日付で記録を残すより安全。
- 「明日」「来週」など未来の予定(投与日・締切など)を記録するときは、確定した「今日」からの
  相対日付として計算し、会話内で以前に出た日付表現をそのまま信用しない。
