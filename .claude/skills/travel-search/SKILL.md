## 目的

会場・日程・人数から、宿と移動手段(飛行機/新幹線)の候補を出し、**すべて円で**比較して代表に報告する。

## 絶対ルール

- **予約・支払い・会員登録はしない**(対外行為。CLAUDE.md 第3項)。予約URLを渡して止まる。
- 金額は**円**で書く。ドルで返ってきた値は換算し、使ったレートと日付を添える。
- 「1人あたり」「1室1泊」「全員往復合計」のどれかを必ず明記する。
- Webで調べた数字には出典と調査日を付ける。

## 最初に確認すること(足りなければ聞く)

会場(住所か施設名) / 日程(往路日・復路日) / 人数と部屋割り(既定: 1名1室) / 出発地(既定: 関西)

## 1. 宿 — `tools/hotel_search/search.py`(楽天トラベルAPI)

- 会場の緯度経度を調べて、半径3kmで検索する。料金は初日の1室1泊。合計目安 = 1室1泊 × 泊数 × 室数。

## 2. 飛行機 — SlickTrip(MCPコネクタ)

- `search_flights`(関西なら origin=`ITM_KIX_UKB`、travelers=人数、往復)→ 候補ごとに `search_return_flights`。
- 料金は**USDの全員往復合計**で返る。円換算レートはWeb検索で当日のUSD/JPYを調べる(このネットワークからは為替APIにつながらない)。
- LCC(Peach等)は受託手荷物が運賃に入っていないことが多いので注記する。
- 残席数(seat_availability)はSlickTripへのログインが必要。最終確認はトラベルコ(https://www.tour.ne.jp/j_air/)か各社サイトで行うよう案内する。

## 3. 新幹線・特急 — `tools/train_search/link.py`(駅すぱあと フリープラン)

- 往路・復路の駅すぱあと結果ページURLを作って渡す(`EKISPERT_KEY` が未設定ならスキップして理由を書く)。
- 所要時間・運賃・乗継はWeb検索で調べて表に書く(フリープランでは数値データが取れないため)。

## 4. 報告フォーマット

1. 移動手段の比較表: 手段 / 往路の便・列車 / 復路 / 所要時間(片道) / 1人往復 / 全員往復合計(円)
2. 宿の候補表: 宿名 / 1室1泊 / 評価 / 全室全泊の目安(円)
3. 総額の目安(移動 + 宿)と、おすすめ1案とその理由(1行)
4. 注意点(手荷物、料金変動、残席未確認など)と、代表に決めてほしいこと
