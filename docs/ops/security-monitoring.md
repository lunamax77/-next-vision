# セキュリティ監視（改ざん・攻撃・情報漏洩に気づく仕組み）

最終更新: 2026-10-23（大量送信ブロック・定期改ざん検知を追加）　担当: プロダクト（仕組み）／代表（通知の確認）

## 当社 HP の前提

- HP は静的 HTML が中心。PHP は問い合わせフォームの受け口 `contact.php` だけ。
- 問い合わせ内容はサーバーに保存せず、メール（data@nextvision.fun）と Google スプレッドシート「リード台帳」に送る。サーバーが侵入されても、そこに顧客データのたまり場は無い。
- 「漏れうるもの」は、サーバー上の `config.php`（Apps Script の URL と合言葉）と、サーバー・GitHub・Google のログイン情報。

## 代表が月1回・5分で見ること

1. GitHub の Actions タブ → 「Site integrity check」が緑で続いていること。
2. Search Console → 左メニュー「セキュリティと手動による対策」→「セキュリティの問題」が「問題は検出されませんでした」であること。
3. コアサーバーのファイルマネージャーで `public_html` を開き、見覚えのないファイル（意味不明な名前の .php、最近日付の更新で心当たりが無いもの）が無いこと。リポジトリに無いファイルは `config.php`・`.htaccess`・`.htpasswd`・`.ftp-deploy-sync-state.json` の4つだけが正常。
4. リード台帳に、明らかに機械的な大量行（同じ内容・数秒おき）が無いこと。あれば迷惑投稿なので、フォームの対策を強化する。

## 「攻撃を受けた／漏れた」と判断したときの手順

1. 止める: コアサーバーで該当ファイルを削除、または `public_html` に Basic 認証をかけて一時閉鎖（`.htaccess`）。
2. 鍵を変える: コアサーバーの FTP パスワード、GitHub の Secrets（FTP_PASSWORD）、Apps Script の合言葉（`config.php` の GAS_TOKEN と GAS 側）、Google・GitHub のパスワード。
3. 戻す: GitHub の Actions で「Deploy site to nextvision.fun」を手動実行し、正本から HP を上書き。`config.php` は手で置き直す。
4. 調べる: コアサーバーのコントロールパネル「アクセスログ」「エラーログ」で、該当日時の不審なアクセス（見慣れない .php への POST など）を確認。ログは控えを保存する。
5. 連絡: 顧客情報（問い合わせの氏名・メール等）が漏れた可能性があれば、該当のお客様への連絡と、個人情報保護委員会への報告要否を代表が判断する（報告は対外行為）。

| フォームの大量送信ブロック（`contact.php`） | 同一IPから10分に3回・1時間に8回、全体で10分に30回を超える送信、ハニーポット、ページを開いて3秒未満の送信を遮断。非公開ログに記録 | 10分に10件以上ブロックすると data@nextvision.fun へ「【HP警告】フォームへの大量送信をブロックしました」（1時間に1通） |

## できていないこと（必要なら追加）

- サーバーのアクセスログの自動監視。コアサーバーのログは外部から取得できないため、月1回の手動確認と、フォーム側の警告メールで代替している（2026-10-23）。
- WAF（Web Application Firewall）: コアサーバーのコントロールパネルに WAF 設定があれば ON を推奨。
