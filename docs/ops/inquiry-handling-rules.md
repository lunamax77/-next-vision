| 項目 | 内容 |
| --- | --- |
| このファイルの目的 | HPフォーム・LINE・電話・メールから来た問い合わせを、**取りこぼさず・1営業日以内に・安全に**対応するための、代表の日次／週次ルーティンと、個人情報・承認のルール |
| 最終更新日 | 2026-09-07 |
| 担当 | 業務管理（ルール管理）／営業（追客フロー `docs/sales/followup-flow.md` の設計・文面ドラフト）／プロダクト（フォーム・記録の仕組み）／代表（返信・判断） |

> 営業担当の追客フロー（`docs/sales/followup-flow.md`）と台帳ガイド（`docs/sales/lead-sheet-guide.md`）が「**何を・いつ送るか**」「**台帳に何をどう書くか**」を決めるのに対し、このファイルは「**代表がいつ何を見て、何を自分で判断するか**」と「**守るべき線**」を決めます。用語（ステータス・温度感）は営業担当の定義に合わせています。

## 1. 問い合わせの入口と、記録される場所

| 入口 | 通知 | 記録される場所 | 状態（2026-09-07） |
| --- | --- | --- | --- |
| HPフォーム（https://nextvision.fun/#contact） | `data@nextvision.fun` にメール通知＋お客様に自動返信（`site/mail-templates/autoreply.txt`「1営業日以内にご連絡」） | Google スプレッドシート **`リード台帳`**（自動で1行追加） | プログラムは完成（`site/contact.php`）。サーバー設定とGAS接続が `setup-checklist.md` No.6〜8 待ち |
| LINE公式アカウント | LINEアプリに通知 | **代表が手動でリード台帳に1行追加** | 開設待ち（`docs/setup/line.md`） |
| 電話（070-1319-2126） | — | **代表が手動でリード台帳に1行追加** | 稼働中 |
| メール（data@nextvision.fun） | メール | **代表が手動でリード台帳に1行追加** | 稼働中 |

**原則：入口が何であれ、必ず `リード台帳` に1行。** 台帳にない問い合わせは「存在しない」のと同じになり、追客が漏れます。

- リード台帳（一次記録）→ 受注が見えてきたら **案件管理表**（`tools/pipeline/案件管理.xlsx`、ステータス「問合せ→ヒアリング→見積提出→受注…」）へ転記。台帳は「全部の入口」、案件管理表は「本気の案件（金額・入金の管理）」と分けます。
- リード台帳の列は `docs/sales/lead-sheet-template.csv` が正：受付日時／流入経路／会社名／担当者名／メール／電話／業種／希望商材／希望時期／会場・エリア／**温度感**／**ステータス**／**次回アクション日**／担当メモ／自動返信済み／ステップメール進捗。
- ステータス（`lead-sheet-guide.md` 第2章の定義）：`新規` → `対応中` → `見積提出` → `受注` ／ `失注` ／ `休眠`。営業メール・スパムは行ごと削除せず、担当メモに「対応不要」と書いて連絡先を消します（第5項）。
- 温度感：`A`（今すぐ客）／`B`（検討中）／`C`（情報収集）。判定基準は `followup-flow.md` 第4章。

## 2. 代表の日次ルーティン（朝10分＋随時）

### 朝（10分、平日 9:30 の受付開始前が目安）

1. **リード台帳を開く**（ブックマークしておく）。**黄色**の行（`新規` のまま12時間以上）と **赤**の行（次回アクション日が今日以前）が上に来るように並んでいます（色は営業担当の条件付き書式、`lead-sheet-guide.md` 第3章）。
2. `新規` があれば、その日のうちに**一次返信**する（下の「1営業日ルール」）。温度感 A/B/C とステータス `対応中`、次回アクション日を入れる。
3. 赤い行（次回アクション日が来ている）を見て、やる／日付をずらす。**次回アクション日は空欄にしない**。
4. 通知メール（`data@nextvision.fun`）と LINE の未読を確認し、台帳に載っていないものがあれば**先に1行追加**する。

### 随時

- **フォーム通知が来たら**：自動返信はすでにお客様に届いています（承認済み文面）。代表がやるのは **1営業日以内の「人の返信」**です。
- **LINEが来たら**：台帳に追加 → 返信。
- **電話が来たら**：通話後すぐ台帳に追加（会社名・担当者名・用件・折り返し先だけで可）→ 確認メールかLINEを送って文字に残す（電話だけで進めない）。

### 1営業日ルール（自動返信で「1営業日以内にご連絡」と約束しています）

- **受付から1営業日以内**（金曜夕方の問い合わせは月曜中まで）に、**代表からの一次返信**を出す。**温度感 A（今すぐ客）は当日中**。
- 一次返信は営業担当の**承認済みテンプレート**（`docs/sales/step-mails.md` 第4章・穴埋め式）をベースに、お客様の内容に合わせて2〜3行だけ変える。所要5分が目安。
- 1営業日以内に本回答（見積など）ができないときも、「受け取りました。◯日までにご連絡します」の**一次返信だけは必ず**出す。

## 3. 代表の週次ルーティン（金曜 15分）

1. **失注・停滞の整理**：`対応中`・`見積提出` のまま **2週間**動きがない行は、次回アクション日を入れ直すか、見込みがなければ `失注`／`休眠` にする（営業担当の定義では「30日以上反応なし」で失注・休眠。2週間時点で一度見直す）。`失注` にするときは担当メモに **失注理由を1行**（`予算` / `日程合わず` / `他社` / `企画中止` / `反応なし` / `その他`）。この1行が、次の記事・提案・価格の改善材料になります。
2. **件数の記録**：今週の「新規件数／1営業日以内に返信できた数／見積提出に進んだ数」を、月次レビューのために台帳の集計欄に残す（集計欄は営業担当が用意）。
3. **次週の次回アクション**：`次回アクション日` が来週の行を眺めて、無理なら日付をずらす。
4. **対応不要の整理**：営業メール・スパムは担当メモに「対応不要」と書き、連絡先欄を空にする（下の第5項）。

## 4. 対外行為の承認ルール（日常業務に落とした形）

憲章（`CLAUDE.md` 第3項）の「対外行為には代表承認」を、問い合わせ対応では次のように運用します。

| 行為 | 誰が実行 | 事前承認 | ルール |
| --- | --- | --- | --- |
| フォームの**自動返信メール** | システム（自動） | **文面を代表が事前承認**（1回） | 承認済み文面**のみ**送られる。文面の変更は営業担当がドラフト → **代表承認** → プロダクト担当が反映 |
| LINEの**あいさつ／自動応答** | システム（自動） | 同上 | 同上。承認前は初期文面のまま |
| **ステップメール①〜③**（翌日・3日後・7日後。`docs/sales/step-mails.md` 第1〜3章。送信手段はGASの時間トリガーを営業担当が提案中） | システム | **各文面を代表が事前承認** | 承認済み文面以外は送らない。承認前は自動送信を動かさない。**個別のお客様への文面変更は、代表が自分で書く場合のみ可**（AIが勝手に変えて送ることはない） |
| 代表の**一次返信・個別返信** | **代表** | 不要（代表本人の行為） | AIは下書きまで。**送信ボタンは代表** |
| **見積の提示** | **代表** | 代表判断 | `tools/invoicing/` で作成 → 代表が内容確認 → 代表が送信。金額・条件は `pricebook.json` の定価どおり。送料の概算表・キャンセル規定は未整備（`followup-flow.md` の要確認） |
| **値引き・特別条件**（定価と違う金額、キャンセル条件の緩和、無償追加など） | **代表** | **代表判断のみ** | AI・担当は提案まで。「値引きできます」とお客様に伝えるのは代表だけ |
| **開催日の確約・仮押さえの約束** | **代表** | 代表判断 | 「◯日は空いています」も約束にあたるため、代表が返答する |
| お客様情報を**外部ツールに入れる**（新しいCRM・メール配信サービス等） | — | **代表承認（外部サービスへのデータ送信）** | 現状は Google スプレッドシート＋メール＋LINE のみ。追加は要承認 |

**原則**：AIは「下書き・台帳更新・リマインド・整理」まで。**お客様に届く行為は、承認済み文面の自動送信を除き、すべて代表が実行**します。

## 5. 個人情報の扱い

問い合わせで受け取るのは、会社名・担当者名・メールアドレス・電話番号・開催内容など。法人の担当者情報でも**個人情報**です。次のルールで扱います。

### アクセス権

| 対象 | アクセスできる人 |
| --- | --- |
| リード台帳（スプレッドシート） | **代表のみ**（会社用 Google アカウント）。共有リンクは「制限付き」のまま。「リンクを知っている全員」にしない |
| 通知メール（data@nextvision.fun） | 代表のみ |
| LINE公式アカウント管理画面 | 代表のみ（スタッフを増やすときは代表が権限「運用担当者」で追加） |
| AI（Claude）への共有 | 台帳の**中身をそのままチャットに貼らない**。AIに相談するときは「会社名・個人名・連絡先を伏せた要約」にする（例：「関西の商業施設、10月開催希望、運営代行込み」）。文面の下書きを頼むときも同様 |
| このリポジトリ | **お客様情報は一切書かない**（サンプル名・仮名のみ） |

### 保管期間

| データ | 保管期間 | 期限が来たら |
| --- | --- | --- |
| 案件化したもの（受注・開催） | 取引記録として **7年**（請求書・契約関連の保存期間に合わせる） | 案件管理表・請求書とセットで保管 |
| 案件化しなかったもの（失注・休眠） | **最終連絡から1年**（営業担当のフローでは失注の半年後に1回だけ再アプローチ。その後に消す） | 連絡先（メール・電話）を消し、会社名と失注理由だけ残す（統計用） |
| 対応不要（営業メール・スパム） | **即時** | 連絡先を消す |
| フォーム通知メール | 台帳に転記後は不要 | 3か月をめどに削除（台帳が正） |

- 年1回（毎年9月、決算や更新作業と同時期）、代表が台帳を上から見て古い行の連絡先を消す。業務管理がリマインドします。

### 削除・開示の依頼が来たとき

1. お客様から「情報を削除してほしい」「何を持っているか教えてほしい」と言われたら、**代表に即エスカレーション**（AI・担当は勝手に返答しない）。
2. 代表は本人確認（問い合わせに使ったメールアドレスからの依頼であること）のうえ、**台帳・通知メール・LINEのトーク**から該当情報を削除し、「削除しました」と返信する。
3. 目安：**依頼から2週間以内**に対応。
4. 削除した事実（日付・「◯月◯日の問い合わせ1件」程度）だけ台帳の備考に残す（連絡先は残さない）。

### 情報漏えいが疑われるとき

- 台帳を間違って共有した、メールを誤送信した等に気づいたら、**まず代表に報告**（隠さない）。代表が影響範囲を確認し、必要ならお客様に連絡する（対外行為＝代表判断）。

### HP側に必要なもの（要確認）

- フォームの近くに **プライバシーポリシー**（利用目的・保管・問い合わせ先）へのリンクが必要です。現状のHPにポリシーページがあるか未確認。**業務管理がドラフトを作成 → 代表承認 → プロダクト担当が掲載**の流れを提案します（要確認事項）。

## 6. 困ったときの判断早見表

| 状況 | どうする |
| --- | --- |
| 明らかに営業メール・スパム | 担当メモに「対応不要」。返信しない。連絡先を消す |
| 内容が個人（家庭のパーティー等）で対象外 | 承認済みの「お断りテンプレート」（営業担当が用意）で丁寧に返信 |
| 値引きを求められた | その場で答えない。「社内で確認して◯日までにご連絡します」→ 代表が判断 |
| 開催日が競合した | 先着ではなく、**代表が判断**。返信は代表 |
| クレーム・トラブル | 電話で代表が直接対応。文面での返信は代表が書く。AIは経緯の整理まで |
| メディア・取材・提携の打診 | 対外コミットになるため**代表が対応**。営業担当が想定問答を用意 |
| 1営業日を過ぎてしまった | それでもすぐ返信する。「ご連絡が遅くなり申し訳ありません」を一言添える。理由は書かなくてよい |
