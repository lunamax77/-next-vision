## No.1 【最優先】サーバー契約の更新（CORESERVER）

| | |
| --- | --- |
| 期限 | **2026-09-18（有効期限）**。本日から **11日** しかありません。今週中に。 |
| 所要時間 | 15分（+ 支払い方法によっては入金確認まで数日） |
| 前提条件 | バリュードメインのログインID／パスワード、支払い手段（クレジットカード等） |
| 対外行為？ | **はい（支払い＝お金が動く）→ 代表が実行** |
| 技術手順 | 特に不要（管理画面の操作のみ。迷ったら下の手順で） |

**やること**
1. ブラウザで **バリュードメイン**（https://www.value-domain.com/）を開き、ログインします。
2. 上部メニューの **「コントロールパネル」→「サーバー」** を開きます。
3. 一覧から **CORESERVER（nextvision.fun を置いているアカウント）** を探し、**「更新」**（または「有効期限の更新」）を押します。
4. 更新期間を選びます。**1年更新を推奨**（毎年この作業が来るのを避けるため）。
5. 支払いを完了します。
6. **自動更新の設定**：同じ画面（または「サーバー」→ 該当アカウントの「設定」）で **「自動更新」を「有効」** にしてください。これで来年以降、期限切れの心配がなくなります。
   - 自動更新にはバリュードメインに「クレジットカード登録」または「残高（前払い）」が必要です。案内に従って登録してください。
7. あわせて **ドメイン（nextvision.fun）の有効期限** も確認してください（「コントロールパネル」→「ドメイン」）。サーバーと期限が別なので、こちらも自動更新を有効にしておくと安心です。

**完了の確認方法**
- 「サーバー」一覧の **有効期限が 2027年以降** になっている。
- 「自動更新: 有効（ON）」と表示されている。
- バリュードメインから「更新完了」のメールが届いている。
- 業務管理への報告：「サーバー更新OK、期限 20XX-XX-XX、自動更新ON」の一行で十分です。

> 注意：もし期限を過ぎてしまっても、多くの場合は一定期間の猶予で復旧できますが、**HPが表示されない期間が発生**し、最悪データが消えます。必ず期限前に。

## No.2 GitHub Secrets に FTP 接続情報を登録（自動デプロイの土台）

| | |
| --- | --- |
| 所要時間 | 15分 |
| 前提条件 | ①GitHub にログインできる ②CORESERVER の **FTP接続情報**（サーバー名・FTPユーザー名・FTPパスワード）が手元にある（バリュードメインの「サーバー」→ 該当アカウント → 「FTP情報」や登録時のメールで確認できます） |
| 対外行為？ | いいえ（自社の設定作業）。ただし**パスワードを扱うため代表ご自身で**入力してください。AIには絶対に渡さないでください |
| 技術手順 | `docs/setup/deploy.md`（プロダクト担当作成予定） |

**やること**
1. ブラウザで GitHub のこのリポジトリを開きます。
2. 上部タブの **「Settings」**（歯車）→ 左メニュー **「Secrets and variables」→「Actions」** を開きます。
3. 緑の **「New repository secret」** ボタンを押し、次の3つを**1つずつ**登録します（Name は大文字・アンダースコアまで正確に）。

   | Name（そのまま入力） | Secret（値） |
   | --- | --- |
   | `FTP_SERVER` | CORESERVER の FTPサーバー名（例の形式: `xxxx.coreserver.jp`） |
   | `FTP_USERNAME` | FTPユーザー名 |
   | `FTP_PASSWORD` | FTPパスワード |

4. 3つ登録できたら、上部タブ **「Actions」** → 左の **「Deploy site to nextvision.fun」** → 右上 **「Run workflow」** → 緑の「Run workflow」ボタンで、手動で1回実行します。

**完了の確認方法**
- Actions の実行結果が **緑のチェック（成功）** になる。
- https://nextvision.fun/ を開いて、HPが**これまで通り表示されている**（壊れていない）。
- 赤い×（失敗）になった場合は、実行結果のページのURLをプロダクト担当に伝えてください。パスワードは伝えなくて大丈夫です。

> このワークフローは `.htaccess` / `.htpasswd` には触らず、「全削除して入れ直す」モードも無効になっています（`.github/workflows/deploy.yml`）。HPが消える心配はありません。
