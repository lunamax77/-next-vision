## 3. 今回直したもの

### 3-1. `site/build_details.py`（詳細ページ生成スクリプト）
- `social()` を新設し、生成する全詳細ページの `<head>` に以下を出力：
  - `<meta name="robots" content="index,follow">`
  - ページ固有の `<link rel="canonical">` と `og:url`
  - `og:type` / `og:site_name` / `og:locale` / `og:title` / `og:description` / `og:image` / `og:image:alt`
  - `twitter:card`(summary_large_image) / `twitter:title` / `twitter:description` / `twitter:image`
  - `og:image` は **各ページのヒーロー写真（＝該当商材の写真）の絶対URL** になるようにした
- `jsonld()` を新設し、`BreadcrumbList`（ホーム → 体験コンテンツ → 当ページ）と `Service`（provider に NextVision）を出力
- favicon（`images/logo.png`）を `<head>` に追加
- `related()` にエア遊具カードを追加。`.rel` を `repeat(auto-fit,minmax(260px,1fr))` に変更し、カード枚数が3枚でも崩れないように
- **`air.html` の生成定義を追加**（下記 3-3）

### 3-2. `site/sitemap.xml`
トップのみ → 全5URL（index / klp / punilab / seal / air）。既存の書式を踏襲。
priority は index 1.0、看板商材の klp 0.9、他3ページ 0.8。changefreq はトップ weekly、詳細ページ monthly。lastmod は 2026-08-24。

### 3-3. `site/air.html`（新規・自動生成）

構成は「LINE-UP → POINT → RENTAL（日額・月額表）→ SPEC → PRICE → CONTACT → OTHER」。

## 4. 今回 **直さなかった** もの（と理由）

| 項目 | 理由 |
|---|---|
| OGP画像の1200×630化 | 画像の新規制作・トリミングが必要で、ブランド表現の判断を伴う。プロダクト単独で決めるべきでないと判断。**マーケ／デザイン側と代表の判断が必要**（下記【要確認】） |
| ゲーム遊具3種の写真差し替え | 実写真がリポジトリに存在しない。存在しない画像の参照は作れない |
| 各商材の `Product` / `Offer` 構造化データ（価格のマークアップ） | 価格が「税別・〜から・別途費用あり」の条件付きのため、`Offer` で単純に価格を宣言すると誤認・リッチリザルトのエラーを招く。`Service` に留めた |
| `sameAs`（SNSアカウントURL）の構造化データ追加 | 公式アカウントのURLが不明。判明次第、`index.html` の LocalBusiness に追加すべき |
| Google Search Console / Analytics のタグ設置 | **外部サービス連携にあたるため代表の承認が必要**。未実施 |
| sitemap の検索エンジンへの送信（ping） | **対外行為のため実施していない**。公開後、代表の承認のもとで Search Console から送信すべき |
| 詳細ページごとの FAQ 構造化データ | index の FAQPage と内容が重複し、重複マークアップになるため見送り |
| 既存3ページの本文・料金・スペックの内容変更 | 監査の範囲外。事実の書き換えは代表の確認が必要 |
| デプロイ・公開・git コミット／プッシュ | **会社憲章 第3項に従い実施していない。** リポジトリ内のファイル編集のみ |

## 5. 【要確認】代表に確認が必要な事項

HPに記載が無く、こちらでは創作していない項目。埋まると拡散・成約の両方に効きます。

1. **OGP用のシェア画像（1200×630）を作ってよいか。** 現在の写真は正方形・4:3 のため、SNSの大カードで上下が切れます。商材ごとにロゴ＋商材名を載せた専用画像を用意するのが最も効果的です。
2. **ゲーム遊具3種（フープショット／ウエスタンフープ／チックタックトゥ）の実写真**はありますか。現在プレースホルダー画像です。
3. **エア遊具の詳細スペック**（HPに記載が無い）
   - カーニバルA / B、ユニコーンターゲット等の設置寸法（W×D×H）
   - 各機種の対象年齢・体重制限・同時利用人数の上限
   - 「安全マージン」の具体的な数値（周囲◯m 等）
   - 月額レンタルの最低契約期間・条件
4. **賠償責任保険の詳細**（保険会社・補償上限）を掲載してよいか。掲載できれば商業施設の稟議で強い材料になります。
5. **開催実績の企業名の掲載可否。** `seal.html` に「楽天モバイル イオンモール高岡店」「ドコモ」の記載があります。**掲載許諾は取得済みでしょうか。** 未取得の場合は先に許諾が必要です（対外的な名義使用にあたるため）。
6. **公式SNSアカウントのURL**（X / Instagram など）。構造化データの `sameAs` とフッタに載せると、拡散→サイト→再拡散の輪ができます。
7. **Google Search Console / Google Analytics の導入可否。** 拡散施策の効果測定に必須ですが、外部サービス連携のため代表の承認が必要です。導入する場合、測定タグの設置と sitemap 送信をセットで行います。
8. **対応エリアの実態**（「大阪発・全国対応」以上の粒度。離島・遠方の扱い、配送料の目安レンジ）。
9. **エア遊具の「所要 常時」の運用**（開催時間中の入れ替え制か、時間指定制か）。air.html には index の記載どおり「常時」とのみ書いています。

## 6. 拡散・SEO上いちばん効く改善（優先順）

1. **詳細ページのOGP実装（完了）** — 拡散の受け皿として最大のインパクト。これが無いと、マーケが何をシェアしても画像なしのリンクになり、クリック率が桁で変わります。
2. **エア遊具の専用ページ（完了）** — 「エア遊具 レンタル」「ふわふわ レンタル 大阪」といった検索と、単体レンタル訴求のシェア先が初めて成立します。
3. **sitemap 全ページ登録（完了）** — インデックスされて初めて検索流入が始まります。**ただし公開後の Search Console 送信は代表の承認待ち。**
4. **OGP専用画像の制作（未対応・要承認）** — 上の1をさらに伸ばす一手。現状の写真でもカードは出ますが、専用画像にすると訴求文がカード上に載るためクリック率が上がります。
