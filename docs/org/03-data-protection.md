# 原本不可侵とデータの扱い(両社共通)

既存データを守るための運用ルール。上位ルールは `CLAUDE.md` 第4-1項。
マスターくんもジョブズも担当AIも、これに従う。

## 原則:原本は動かさない

代表・会社がすでに持っているファイル(スプレッドシート、議事録、各種ドキュメント・データ)は
会社の **原本** であり、AIにとって **読み取り専用** とする。

**禁止(AIはやってはいけない):**

- 原本の上書き・追記・編集
- 原本のセルや行の書き換え・削除
- 原本のファイル名変更・移動・削除

**許可(AIがやってよい):**

- 原本を**開いて読む・参照する・参考にする**
- 参照した上で、**別の新しいファイル**として成果物を作る
- 作った成果物を **AIの作業場** に格納する

## 成果物はどこに置くか

| 会社 | AIの作業場(成果物の置き場) |
| --- | --- |
| ドリームクリエーション | Googleドライブ「AI専用」フォルダ(成果物は `09_成果物`、台帳は各分野フォルダ内に新規作成) |
| ネクストビジョン | このリポジトリ(社内文書・ドラフト・計画など) |

## 成果物の作り方(トレーサビリティ)

原本を書き換えたと誤解されないよう、生成物には次を残す。

- **いつ**作ったか(作成日)
- **何を参照**して作ったか(元になった原本・議事録の名前など)
- これはAIが作った**下書き**であること

## 原本に触りたくなったら

「原本を直接更新したほうが早い」とAIが判断しても、**実行してはいけない。**

1. 一度止まる。
2. 「原本のここを、こう更新したい」と代表に提案する。
3. 原本を更新できるのは **代表だけ**。承認が出るまで原本には触れない。

これは対外行為(`CLAUDE.md` 第4-2項)に準じた承認事項として扱う。

## 個人情報の注意

人材・人事に関する原本(例: ドリクリの `04_人材管理`)は個人情報を含む。
フォルダごと第三者に共有すると人事情報も見えてしまうため、共有範囲は**代表個人に絞る。**
AIはこれらを外部に送る・共有する前に必ず代表の承認を取る。
