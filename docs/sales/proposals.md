# 商談化率を上げるためのHP改善提案

> 営業担当AIのドラフト（社内文書 / L0）。実装はプロダクト担当に回す前提で、内容だけを書く。
> 根拠はHP（`site/index.html`）の現状と、問い合わせ後の追客フロー（`followup-flow.md`）で必要になる情報から。

| # | 提案 | 現状 | 根拠・期待する効果 |
|---|---|---|---|
| 1 | **料金の「含む・含まない」を1枚の表にする** | 「機材レンタル費・税別」「スタッフ含まず」「送料実費」「運営代行は個別見積」「2日目以降50%目安」が料金表・注釈・シミュレーターに分散している | 担当者が上司に説明するとき最初に聞かれるのが「結局いくらか」。含む（機材一式・手順書・運営マニュアル・オンライン説明・賠償責任保険）／含まない（送料・運営スタッフ・電源・会場側の備品）を1表にすれば、見積後の「思っていたのと違う」を減らせる。ステップメール②の早見表と同じ内容をHPに置くことで、メールからの導線先としても機能する |
| 2 | **問い合わせフォームに「電話番号（任意）」「会場の所在地（都道府県）」「開催時期」の項目を足す** | 現行フォームは 会社名・担当者名・メール・ご希望の体験・自由記述のみ。日程と会場は自由記述に頼っている | 温度感の判定（`followup-flow.md` 第4章）と送料概算に必要な情報が最初から揃うため、一次返信の往復が1回減る。都道府県と時期はプルダウンにして入力の負担を増やさない。電話番号はA客への即時連絡に必要だが必須にはしない |
| 3 | **「開催までの流れ」に、各ステップで「お客様にしてもらうこと」と「日数の目安」を添える** | 6ステップの見出しと一言だけ（「会場図面・広さ確認」など） | 「1か月前が目安」の根拠が見えると、担当者が社内の稟議スケジュールを逆算できる。例：ヒアリング（図面と電源情報を送付・1〜3日）→ 見積（当社から2〜3営業日で送付）→ 契約（1週間）→ 準備（2週間）。追客フローの「代表が24h以内に返信」もここに書けば、自動返信との整合が取れる（要確認：日数を約束する形になるため代表判断） |
| 4 | **よくある断り文句への先回りをFAQに追加する** | FAQは広さ・スタッフ・電源・雨天・自社運営・時期の6問 | 追客で想定される保留理由に先に答えると、見積提出後の沈黙が減る。追加案：「人手がない」→運営代行と設営・撤収のみ代行の2段階がある／「予算が合うか分からない」→シミュレーターで日数と組み合わせを変えると概算が出る、月額プランあり／「施設側に提出する書類は」→賠償責任保険の証明書類を提出できる／「小さいスペースしかない」→ワークショップは6畳程度、エア遊具は単体レンタル可／「キャンセル料は」→（HPに記載がないため**要確認**：キャンセル規定を決めてから掲載） |
| 5 | **写真・動画の「開催イメージ」を1ページにまとめ、担当者が社内共有しやすくする** | 写真は各商材ページとギャラリーに分散。実績は施設カテゴリのテキストチップのみ（社名非掲載ポリシー） | 担当者が上司や本部に「こういうイベントです」と見せる材料が1URLで済むと、社内説明のハードルが下がる。社名は出さず「大型商業施設・館内イベントスペースでの開催例」のようにカテゴリ表記で、こども免許証・ワークショップの手元・エア遊具の賑わいを並べる。ステップメール②とLINEからの導線先にもなる。掲載写真は開催後フォローで許可を得たものに限る |

## 優先順位（営業からの提案）

1. 提案2（フォーム項目）— 追客フローの前提になる。PHPフォームの実装と同時に入れるのが最も低コスト。
2. 提案1（含む・含まない表）— 見積後の齟齬防止。既存の情報を並べ替えるだけで作れる。
3. 提案4（FAQ追加）— キャンセル規定以外は既存の記載から書ける。
4. 提案3・5 — 代表判断（日数の約束・写真の掲載許可）が要るため、後回しでよい。
