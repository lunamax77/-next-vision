# LINE WORKS 定時確認ルーティン(代表PC限定・ブラウザ自動化)

## 位置づけ

- **目的**: LINE WORKS上の新着・重要そうなメッセージを、他の定時報告(朝8/昼12/夕18/夜21・
  `daily-report-routines.md`)と同じような形で確認・報告する。
- **なぜ別立てか**: `browser`スキルのモードB(CDP接続、代表がログイン済みのブラウザに接続)は
  **代表のPC上でのローカル実行でしか使えない**(クラウドのブラウザは代表PCのログイン状態を
  持っていない)。クラウドの4回の定時報告(`daily-report-routines.md`)には組み込めないため、
  LINE WORKSの確認だけ**代表PC上のローカル実行(ローカルのClaude CodeまたはCodex)で別途定時実行**する。
- **読み取り専用**。返信・スタンプ・リアクション等の操作は一切行わない(`browser`スキルの
  「承認なしで進めてよい操作」の範囲内 = 読み取りのみ)。開いて見ることで既読になるのは
  やむを得ない副作用として許容するが、既読化そのものを目的とした操作はしない。

## 実行方法

- `browser`スキル(モードB・CDP接続)を使い、代表がログイン済みのChromeに接続してLINE WORKSの
  Web版を開く。
- 初回セットアップ(Chromeのデバッグ起動、CDP接続方法)は `.claude/skills/browser/reference/setup.md`
  を参照。

## チェック内容

1. トークルーム一覧を開き、前回チェック以降に新着があるトークルームを確認する。
2. 新着メッセージのうち、締切・確認依頼・業務連絡など重要そうな内容を優先的に拾う。
   広告・自動通知・雑談は他の定時報告と同じく間引いてよい。
3. 【LINE WORKS 新着(前回比)】として、トークルーム名・送信者・時刻・内容の要約を
   時系列でまとめる。

## 差分の出し方(前回比)

`skills/stateless-periodic-reporting-pattern.md` のチェックポイント方式を踏襲する。

- チェックポイントファイル: ローカルの作業用フォルダに `lineworks-checkpoint.json` を置き、
  トークルームごとに「最後に確認したメッセージの時刻/ID」を保存する
  (LINE WORKS側のデータには一切書き込まない、ローカルの記録ファイルのみ)。
- 実行のたびに、保存済みチェックポイントと現在の状態を比較して新着分だけを報告し、
  報告後にチェックポイントを更新する。
- チェックポイントファイルの置き場所は実行環境(ローカルのClaude Code/Codexの作業ディレクトリ)
  に合わせて代表側で決めてよい。存在しない場合は初回実行時に新規作成する。

## 出力・報告

- 他の定時報告と揃えやすいよう、同じトーン・フォーマット(見出し+箇条書き)で出す。
- 新着が無ければ「新着なし」とだけ報告する(無理に長い報告にしない)。
- 通知方法はローカル実行時の環境の設定に準じる。

## スケジュール設定(代表側の作業)

ジョブズ側(クラウドセッション)からは代表PC上のスケジュールを設定できないため、
以下のいずれかで代表ご自身に設定していただく必要がある。

- **Windows**: タスクスケジューラで、指定時刻に「ローカルのClaude Code(または`codex`)を
  下記プロンプトで起動する」コマンドを登録する。
- **Mac/Linux**: `cron` または `launchd` で同様に登録する。
- 頻度・時間帯(クラウドの4回と揃えるか、もっと少なくするか)は代表の運用に合わせて決めてよい。

## 実行プロンプト(そのまま使える文面)

```
あなたはジョブズ配下のプロダクト担当AIです。代表PC上でローカル実行しています。
`browser`スキル(モードB・CDP接続、代表ログイン済みのブラウザ)でLINE WORKSを開き、
読み取り専用で新着メッセージを確認してください。返信・既読化操作・スタンプ等は一切行わないこと。

1. トークルーム一覧を確認し、前回のチェックポイント(lineworks-checkpoint.json)以降の
   新着メッセージを洗い出す。チェックポイントが無ければ「直近数時間分」を対象にしてよい。
2. 広告・自動通知・雑談などノイズは間引き、締切・確認依頼・重要な業務連絡を優先的に拾う。
3. 【LINE WORKS 新着(前回比)】として、トークルーム名・送信者・時刻・要約を時系列でまとめて
   報告する。新着が無ければ「新着なし」とだけ報告する。
4. 報告後、チェックポイントファイルを最新の状態に更新する。
5. 日本語で出力する。原本不可侵・対外承認ルールを厳守し、返信や既読化などの操作は一切しない。
```
