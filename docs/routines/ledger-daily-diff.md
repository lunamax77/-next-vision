# 売掛・買掛 変化トラッキング(手順書)

参照スプレッドシートの売掛・買掛について、**すべての定時報告(朝・昼・夕・夜)で**
「前回チェックからどう変わったか」がわかるようにする仕組み。

## なぜスナップショットが要るか

参照シートは**月ごとのタブ**が上書きで更新されていくため、シートを見ても「前回いくらだったか」は残っていない。
そこで**定時報告のたびに、その時点の値を別ファイルに記録**しておき、直前の記録と比較して増減を出す。

> **原本は読むだけ。** スクリプトは参照シートを `getValues()` で読むのみで、書き込み・編集は一切しない。
> 記録も比較結果も、AI専用フォルダ内の**新規ファイル**として作る(憲章 4-1 原本不可侵)。

## 全体の流れ(1日4回)

```
[参照シート(月タブ)]  ← 読むだけ
   │ ① 各定時報告の少し前に Apps Script が当日時点の売掛・買掛を読む
   ▼
[AI専用/10_売掛買掛スナップショット/2026-08-21_0752.json]  ← そのチェック時点の記録
   │ ② 直前のチェック(＝前回の記録)と突き合わせて増減を計算
   ▼
[_売掛買掛レポート_2026-08-21_0752.txt]  ← 変化レポート
   │ ③ 各定時報告がこれを読んで要約
   ▼
[プッシュ＋メールで通知(＋HTMLレポートのリンク)]
```

**1日の中でのふるまい:**

| 何回目 | 内容 |
| --- | --- |
| 1回目(朝) | 直前の記録は前日のもの → **前日比**を出す |
| 2回目(昼) | 直前の記録は今朝のもの → **前回比 ＝ 本日の累計**(1本のセクション) |
| 3回目(夕) | **前回(昼)比**と**本日の累計(今朝比)**の2セクション |
| 4回目(夜) | **前回(夕方)比**と**本日の累計(今朝比)**の2セクション |

翌朝また1回目に戻り、前日比から再開する。

## セットアップ

`daily-ledger-snapshot.gs` を使う。

1. https://script.google.com/ → 新しいプロジェクト → コードを貼り付けて保存
2. **まず `inspectLedger` を実行**して権限を承認。
   実行ログに、検出したタブと売掛・買掛の項目・合計が出る。
   **意図どおり拾えているかここで確認する**(この関数は何も書き込まない)。
3. 問題なければ `ledgerCheckpoint` を一度実行 → 1回目の基準値が記録される。
4. トリガー →「時間主導型 / 日付ベースのタイマー」を**4つ**登録する。関数はすべて `ledgerCheckpoint`。
   各定時報告より少し前に用意されるよう、次の時間帯にする:
   - **午前7時〜8時**(→ 朝8時の報告用)
   - **午前11時〜12時**(→ 昼12時の報告用)
   - **午後5時〜6時**(→ 夕方18時の報告用)
   - **午後8時〜9時**(→ 夜21時の報告用)

> 以前のバージョン(1日1回・毎朝のみ)で `dailyLedgerSnapshot` のトリガーをすでに設定済みでも、
> そのまま動く(内部で `ledgerCheckpoint` を呼ぶ互換関数がある)。ただし1日1回のままなので、
> 昼・夕・夜でも変化を見たい場合はトリガーを上記の4つに差し替える。

## 出力されるレポートの例

**昼(2回目・その日はじめての変化):**
```
【前回(0800)からの変化 ＝ 本日の累計】
  [8月 / 売掛] 合計 17,200,146  (+854,100)
      [増] ネクセル  14,217,545 → 15,071,645  (+854,100)
  [8月 / 買掛] 合計 8,774,645  (±0)
      変化なし
```

**夕方(3回目以降・2セクション):**
```
【前回(1200)からの変化】
  [8月 / 売掛] 合計 16,481,754  (-718,392)
      [減] エディオン  1,618,392 → 900,000  (-718,392)
  [8月 / 買掛] 合計 8,449,645  (-325,000)
      [消滅] エグボック  325,000 → なし

【本日の累計変化(今朝 0800 比)】
  [8月 / 売掛] 合計 16,481,754  (+135,708)
      [増] ネクセル  14,217,545 → 15,071,645  (+854,100)
      [減] エディオン  1,618,392 → 900,000  (-718,392)
  [8月 / 買掛] 合計 8,449,645  (-325,000)
      [消滅] エグボック  325,000 → なし
```

- **動いた取引先だけ**を挙げる(変化がなければ「変化なし」)。
- 並び順は**増減額の大きい順**。
- 区分は 増 / 減 / 新規 / 消滅 の4種類。

## 読み取りの仕組み(調整するとき)

- タブごとに「**売掛**」「**買掛**」が同じ行に並ぶ見出し行を探し、その下を項目として読む。
- 売掛は「売掛」列から「買掛」列の手前まで、買掛は「買掛」列から行末まで。
- 各行で「**金額(数値)より前にある文字列**」を取引先名、「**最初に現れる数値**」を金額とみなす。
  → 見出し列より左の備考(例: 社長作成、1営業日17時)や、金額より後ろのラベル(例: 個人事業主)は自然に除外される。
- 「売掛/買掛」の見出しが無いタブ(スタッフ稼働表など)は自動でスキップされる。

うまく拾えない項目があれば、`inspectLedger` のログを見て、`HEADER_SEARCH_ROWS` / `BLOCK_MAX_ROWS` や
`pickPair_` の判定を調整する。

## 注意点

- スナップショットは`YYYY-MM-DD_HHmm.json`の形で時刻ごとに溜まる。手動で複数回実行した場合も、
  同一タイムスタンプ(同じ分)の再実行のみ上書きされ、それ以外は新しい記録として増える。
- 金額が `0` の行も記録される(0 → 金額あり、は「増」として出る)。
- 各定時報告のプロンプトは、常に**その時点で一番新しい** `_売掛買掛レポート_` ファイルを読む設計。
  トリガーの実行が何らかの理由で遅れて報告時刻に間に合わなかった場合、報告は1つ前(前回)のレポートを
  読むことになる(古い内容だが、エラーにはならない)。
