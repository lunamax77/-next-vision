# 位置情報の取り扱いルール (社内ドラフト)

> 本書は**社内ドラフト**です。対外的に配布・提示する前に代表の承認を得てください
> (CLAUDE.md 第3項)。法的な最終判断は弁護士・専門家の確認を前提とします。

## 1. なぜルールが要るか

位置情報は「その人がいつどこにいたか」を再現できるデータです。
自宅・勤務先・通院先・信仰・交友関係まで推定できてしまうため、
氏名やメールアドレスより機微度が高いものとして扱います。

日本の個人情報保護法では、位置情報の履歴は特定の個人を識別できる形になれば
個人情報として扱われます。**「業務用の端末だから」「会社が配った端末だから」だけでは
本人同意を省略する理由になりません。**

## 2. 絶対にやらないこと

- 本人に知らせずに位置を収集する
- 本人が停止できない形で収集する
- 業務時間外・私用端末の位置を、本人の明確な同意なく収集する
- 取得した位置を、説明した目的以外に使う
- 第三者 (取引先・パートナー) に位置データを渡す (代表の承認と本人同意が前提)

このデモの実装は、上のうち技術的に防げるものは仕組みで防いでいます
(共有セッションがなければサーバーが受け取らない、常駐通知を消せない、等)。
**その仕組みを外す改造は行いません。**

## 3. 収集する前に決めること

実際に人の位置を集める案件では、着手前に次を文書化して代表の承認を取ります。

| 項目 | 例 |
| --- | --- |
| 目的 | イベント当日のスタッフ配置最適化 |
| 対象者 | 当日稼働の自社スタッフ 8 名 |
| 期間 | 2026-09-05 09:00〜18:00 のみ |
| 取得項目 | 緯度・経度・精度・時刻・電池残量 |
| 保存期間 | イベント終了後 7 日で全削除 |
| 閲覧できる人 | 当日の現場責任者 1 名 + 代表 |
| 保存場所 | 自社サーバー (外部サービスへは送らない) |
| 停止方法 | アプリの停止ボタン。理由の申告不要 |

## 4. 同意の取り方

口頭だけで済ませず、上の表の内容を書面 (または社内チャットの記録) で示し、
本人が「はい」と答えた記録を残します。

同意文の最低限の要素:

1. 何を集めるか (位置と時刻)
2. 何のために使うか (具体的な業務目的)
3. いつからいつまでか
4. 誰が見られるか
5. いつ消えるか
6. **いつでも止められること、止めても不利益がないこと**

6 番目が特に重要です。断ると評価に響く状況では、それは同意として成立しません。

## 5. 保管と削除

- 保存期間は目的に対して最短にします (このデモの既定は 72 時間)。
- 期間経過後の削除は自動で走らせます。手作業の削除運用にしません。
- 本人からの削除要求には、理由を問わず応じます (アプリの全削除ボタン)。
- 案件終了時は DB ファイルごと削除し、バックアップからも消します。

## 6. 端末を渡すとき

社用端末にこのアプリを入れて貸し出す場合も、上と同じ扱いです。
「端末に最初から入っていた」は説明したことになりません。
貸出時に、共有中の表示 (常駐通知 / 青いインジケータ) と停止方法を実際に見せて説明します。

## 7. インシデント時

トークンの漏洩、DB ファイルの流出、意図しない範囲への共有が起きた場合:

1. 直ちに収集を停止し、トークンを再発行する
2. 代表に報告する (対外的な連絡・公表は代表の判断を待つ)
3. 影響範囲 (どの端末の、いつからいつまでのデータか) を記録する
4. 対象者への連絡は代表の承認後に行う
